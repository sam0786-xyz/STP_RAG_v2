# STP-RAG Workbench

A static demonstration and research dashboard for the STP-RAG paper. It is built with Vite, React and TypeScript, and needs no backend: the one model it uses (for semantic chunking of your own text, and for retrieval) runs in the browser.

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # browser ports vs the Python reference, plus rules for all six techniques
npm run build      # static site in dist/; serve with `npm run preview` or any static host
```

Open the site over HTTP. Browsers block the data files when `index.html` is opened directly from disk.

## Pages

Four pages, from simplest to most technical. **[HOW_TO_USE.md](HOW_TO_USE.md)** walks through each one. The same guide opens in the app with the **How to use** button or the `?` key, and **Guided tour** sets up seven views in turn for presenting.

| Page | What you do |
| --- | --- |
| 1. Playground | Cut one short text six ways (fixed size, fixed + overlap, sentences, recursive, semantic, STP); press Play to watch each decide; compare two; paste your own text; download the chunks |
| 2. Try it | Ask a question (preset or your own); a real embedding model retrieves each technique's best chunks; switch on the same word budget |
| 3. How STP works | The four signals on the paper's Sections 1–3; presets and two sliders; click a chunk to read it |
| 4. Evidence | Pilot results with the audit's five problems; the next run's hypotheses and a drop zone for `run_bundle.json` |

Every view has its own address (`#/play?s=guide&t=stp&t2=semantic`, for example), so a link reproduces what you see.

## The in-browser model

Semantic and STP chunking of pasted text, and all retrieval on Try it, use `Xenova/bge-small-en-v1.5` (fp16 ONNX, about 65 MB) through transformers.js in a Web Worker. It reproduces the fastembed similarities used for the precomputed samples to about 0.001. The first **Load the model** downloads it from huggingface.co, and the browser caches it. For an offline copy, run `node scripts/fetch_model.mjs` once. It writes `public/models/`, which is then used automatically and copied into `dist/` by the build. Delete that folder to go back to downloading.

## Data files (`public/data/`)

- `pilot.json`: copied from `paper/results/pilot_metrics.json`. That file is generated by `paper/scripts/make_results.py`, so the paper and the dashboard share one source.
- `demo.json`: built by `scripts/build_demo.py`, which needs `fastembed`. It embeds the manuscript sentence by sentence with `BAAI/bge-small-en-v1.5`, then runs the `stp_eval` reference implementation.
  - The boundary weights are hand-set, because no development split exists.
  - The scalers are fitted on this one document.
  - The six questions were written for illustration.

  The dashboard says all of this on the pages that use it.
- `playground.json`: built by `scripts/build_playground.py` (needs `fastembed`) from `scripts/playground_samples.json`.
  - The four sample texts, their topic labels and their questions were written for the dashboard; places and companies in them are fictional.
  - The file holds neighbour-sentence similarities, plus STP scalers fitted on a reference corpus: the samples and the paper's Sections 1–3.
  - It also holds a parity record that `src/lib/chunkers.test.ts` checks the browser code against.
  - The STP weights are the same hand-set values as `demo.json`, not tuned on the samples.
- `synthetic_run.json`: built by `scripts/make_synthetic_bundle.py` from random records, through the real harness. It is flagged `synthetic` and always shown under a red banner. It exists to test the Evidence page and must never be cited.

## Design notes

- **Accent:** one accent, a deepened form of the paper's STP green (`#0B6E5A`).
- **Method colors:** the Okabe–Ito colors used in the paper's figures.
- **Type:** IBM Plex Sans for the interface; IBM Plex Serif only for corpus text.
- **Chunk tints:** five soft fills that cycle, so neighbouring chunks always differ; a red ✂ badge marks a cut inside a sentence.
- **Motion:** one signal-trace draw when How STP works loads, and the Play replay. Elsewhere, motion only accompanies a state change: bars morphing after a slider moves, tab and toggle indicators, the drawer and the tour card. Reduced-motion settings are respected through `MotionConfig`.
- **Layout:** checked at 1440px and at a true 390px (device emulation) with no horizontal scroll.
